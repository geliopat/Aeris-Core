Утверждённый порядок, без обещания сроков. Фактический прогресс и незавершённые ветки — [STATUS.md](STATUS.md); таблица задаёт требования, а не подтверждает реализацию. Первый Release только при выполнении критериев TESTING.

Контракты API/IPC проектируются достаточно рано для параллельной разработки GUI; не требуется ждать этапа 12 для проектирования и тестовых mock-клиентов. В релизе заглушки не допускаются. Каждый этап сопровождается документацией и тестами, а не только компиляцией. Nightly публиковать при изменениях и успешных обязательных проверках, Release вручную после полного gate. Не менять FlClashZ.

## Репозитории

- Aeris-Core: Rust, ядро, CLI, служба, драйверная интеграция, API/IPC, тесты.
- Aeris: WinUI 3, подписки/GUI, установщик, интеграционные тесты.
- Aeris-Resources: TLS fingerprints, стратегии, Lua-ресурсы, списки, геоданные и provenance.

Публичные, отдельные main/development branches, Actions, релизы и версии. Точные лицензии — после аудита, до копирования. Общий контракт и матрица совместимости доступны всем репозиториям. Документация единая RU/EN, GitHub Pages, поиск, отдельно Release/Nightly, примеры валидируются CI.

## Отслеживание эталонов

| Источник | Проверка | Объект |
|---|---|---|
| Xray-core | 6 ч | XHTTP/XUDP/VLESS/REALITY/Vision |
| Mihomo сборки FlClashX | 24 ч | YAML, протоколы, API, fixes |
| MIPS | 24 ч | RIPS эталон |
| Zapret2 | 6 ч | DPI/Lua API |
| Flowseal | 6 ч | Стратегии и списки |
| zapret2-gui | 24 ч | Каталоги/улучшения |
| uTLS, rustls | 24 ч | Fingerprints, TLS/security |
| Wintun, WinDivert | 24 ч | Драйверы |

Actions проверяет изменения, создаёт отчёт/задачу или PR, прогоняет тесты, затем проверенное изменение можно слить. Не переносить автоматически чужой программный код в Rust. Ресурсы — автоматическое обновление после проверки подписей, лицензии и совместимости. Особый приоритет XHTTP и Zapret2. Точные upstream URLs/refs закрепить после проверки источников.

## Первоначальная подготовка (исторический checklist; актуальные результаты в STATUS.md)

1. Уточнить владельца и доступность названий репозиториев/бренда, лицензии и исходные refs.
2. Зафиксировать схемы YAML, заголовков, CLI/API/IPC и безопасность доверия к обновлениям.
3. Настроить локальную или self-hosted Windows test environment для сетевых драйверов.
4. После отдельного разрешения создать репозитории и начать этап 1.
