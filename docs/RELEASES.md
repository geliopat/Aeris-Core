# Release and Nightly — gates

Independent versions start at 0.1.0. Release requires manual approval and the full [Release 1.0.0 gate](TESTING.md#5-release-gate-100) and applicable core-client checks. Nightly requires actual implemented functionality, passing mandatory CI, and a change since its previous build; use a unique UTC date/run identifier. Never publish unsigned manifests or unsupported driver packages. Initial CI only builds/tests the scaffold; no publication, signing, or automatic release workflow is enabled. Add release automation only after signing trust roots, artifact layout, rollback and real Windows validation are established. Preview channel is excluded.

## Approved details / Уточнения

- Release — канал по умолчанию, ручная публикация после полного gate; Nightly — автоматическая сборка/публикация при изменениях после готовности безопасного pipeline и прохождения обязательных проверок. Предрелизная SemVer форма `1.1.0-nightly.20261126` — согласованный пример, не обещанная версия; уникальность при нескольких сборках в дату обеспечить отдельным run identifier/полем манифеста либо документированной совместимой схемой, без неоднозначного сравнения версий.
- Возможность явного возврата Nightly → Release, если безопасна миграция; при несовместимости остановиться с диагностикой. Не сбрасывать настройки молча.
- Проверка обновлений каждые 24 ч; скачивать только изменившиеся компоненты; установка клиента/ядра по подтверждению, ресурсы по настройкам, драйверы с подтверждением. Раздельные совместимые версии клиента, ядра, службы, API/IPC v1+, ресурсных наборов и драйверов. Отдельные подписанные манифесты каналов; альтернативный URL не меняет доверенные ключи. Atomic rollback.
- Текущие доказательства CI и границы реализованного — [STATUS.md](STATUS.md). Успешная сборка каркаса не разрешает выпуск Release 1.0.0.

## Режимы CI и происхождение выпуска

- **FAST** используется для обычной разработки. Допустимы совместимые кэши зависимостей, компиляции и проверенных готовых компонентов. При совпадении полного ключа подтвердить целостность перед использованием. Все обязательные тесты выполняются.
- **FULL** пересобирает все собственные компоненты. Допустим кэш инструментов и закреплённых зависимостей. Все обязательные тесты выполняются.
- **CLEAN** получает и проверяет закреплённые зависимости заново, без restore/save GitHub Actions Cache, sccache и переиспользования прежних собственных сборок. Выполняются все обязательные тесты.

Каждый режим доступен через ручной запуск сборочного workflow. Nightly сохраняет прежние условия и использует проверенные совместимые артефакты. Release требует CLEAN каждого собственного компонента, прохождения прежних критериев и отдельного разрешения владельца. На подписание и упаковку поступают точные артефакты этих запусков с проверенным происхождением, версиями, манифестами, подписью там, где применима, и контрольными суммами. Релизные привилегии изолированы от PR и кэшей.
