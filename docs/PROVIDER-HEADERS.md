# Aeris — HTTP-заголовки подписок

Согласованный перечень функций. Окончательная грамматика значений, единицы измерения, ограничения длины и приоритеты legacy-ключей закрепляются до реализации. Заголовки относятся к клиенту; сетевые параметры ядра — YAML.

## 1. Идентификация

Remnawave: отдельное правило ответа для UA `Aeris/v0.1.0 core/v0.1.0 Platform/windows` (фактические версии клиента и ядра). Отдельный адаптированный Mihomo-шаблон. HWID стабилен между запусками и обновлениями одного устройства. В простом режиме всегда передаётся и отключение недоступно. В полном включён по умолчанию, пользователь может выключить. Не использовать для телеметрии; точный формат и имена исходящих HWID-заголовков проверить по Remnawave/FlClashZ до реализации. Не передавать секреты и HWID посторонним источникам ресурсов.

## 2. Стандартные и клиентские заголовки

| Заголовок | Назначение |
|---|---|
| `profile-title` | Название активной подписки |
| `announce` | Текст провайдера; plain/base64, переносы строк, emoji, HTTP(S)-ссылки с подтверждением |
| `service-logo` | Логотип провайдера |
| `support-url` | Ссылка поддержки |
| `profile-web-page-url` | Сайт провайдера |
| `profile-update-interval` | Интервал обновления подписки |
| `subscription-userinfo` | Использованный/общий трафик, срок действия по формату источника |
| `profile-auto-update` | Автоматическое обновление |
| `profile-update-route` | Маршрут загрузки подписки |
| `profile-renew-url` | Продление подписки |
| `profile-hwid` | Настройка HWID с ограничением простого режима |
| `profile-expiry-notify` | Порог уведомления об окончании срока |
| `profile-traffic-notify` | Порог уведомления о трафике |

Новые Aeris-специфичные функции используют префикс `aeris-`; сохранять стандартные/согласованные profile-* имена и при необходимости совместимые prefixed-варианты после уточнения контракта.

## 3. Aeris-специфичные

| Заголовок | Назначение |
|---|---|
| `aeris-special` | Список флагов (см. ниже) |
| `aeris-view` | Представление страницы прокси (list/tab, sort, layout, card, icon, hidetimeout согласно поддерживаемой грамматике) |
| `aeris-serverinfo` | Указание основной прокси-группы (plain/base64 по эталону) |
| `aeris-background` | Совместимая базовая настройка фона; не расширять до управления персонализацией |
| `aeris-zapret-strategies-url` | Дополнительный каталог стратегий |
| `aeris-zapret-lists-url` | Дополнительный источник списков |
| `aeris-zapret-autostart` | Автозапуск Zapret2 |
| `aeris-speed-test-url` | URL проверки скорости через VPN |
| `aeris-connectivity-check-url` | URL проверки доступности интернета |
| `aeris-ip-check-url` | URL определения выходного IP |
| `aeris-update-url` | Альтернативный манифест обновлений, без отмены проверки подписей |

Флаги `aeris-special`: `providermode` — полный режим, `onegroup` — одна указанная прокси-группа, `noglobal` — скрыть глобальный режим, `onlytun` — только TUN. Отсутствие providermode — простой режим. Ручного переключателя нет. Комбинации с `full` не используются. Применение сразу после успешного обновления/смены подписки. Неподдерживаемые флаги игнорировать с диагностикой, не применять неизвестные команды.

## 4. Поздние решения — исключения

Не поддерживать как управление: `hideip`, `denywidgets`, `widgets`, `simple`, `full`, `nooverride`, `noedit`, `noexport`, `nozapret`, `nologo`, `noservice`, `managed-settings` (не добавлять как новые флаги). IP всегда скрыт в простом, всегда виден в полном, если определён; виджеты нельзя менять в обоих. YAML подписки всегда read-only, пользовательские правила разрешены и имеют приоритет. Нет общего appearance/theme/accent заголовка; базовый дизайн и пользовательская персонализация. Ранее утверждённый `background` — сохранить в ограниченном объёме, точное взаимодействие с пользовательской темой проверить. Анонс только в простом режиме, внутри карточки подписки без заголовка и сворачивания.

Не дублировать YAML: vpn-mode, tun-stack, routing-mode, kill-switch, DNS/transport/rule/healthcheck параметры групп. Не вводить отдельные zapret-enabled/strategy/mode/autoselect/test-interval, diagnostics-url, update-pre-url/channel/minimum-version/resources-url как новые заголовки без отдельного согласования.

## 5. Совместимость и валидация

Сохранять совместимость поддерживаемых ключей FlClashX и FlClashZ (например `flclashx-special`, `flclashz-special`, `*-view`, `*-serverinfo`, `*-background`). Поздние правила Aeris имеют приоритет: legacy hideip/widgets не меняют жёсткий интерфейс. Старый providermode в Aeris означает утверждённый полный режим, а не копию старого дашборда. Предлагаемый приоритет парсера: Aeris → FlClashZ → FlClashX, не объединять конфликтующие политики; это проектное решение для проверки. Дубликаты, пустые/ошибочные значения, регистр и кодировки покрыть тестами. Применять заголовки атомарно вместе с рабочей конфигурацией; сбой загрузки сохраняет предыдущие.

HTTP(S)-ссылки подтверждать при открытии пользователем. Источники ресурсов/манифесты проверять по политике HTTPS, доверенным ключам, совместимости, хэшам и ограничениям размера; заголовок не может запускать произвольные файлы, отключать проверку обновлений или повышать привилегии. Не делать автоматический переход по ссылкам анонса. URL подписки и HWID считать чувствительными данными.

## 6. Эталон синтаксиса для реализации

Сохранить поддерживаемый синтаксис view фактического FlClashZ, включая пример `aeris-view: proxies.type:list;proxies.sort:none;proxies.layout:loose;proxies.card:compact;proxies.icon:plain` (адаптация известного legacy-примера, не тестированный контракт). Значения и кодирование `hidetimeout`, `special`, `serverinfo`, HWID, profile-* и precedence сверять с исходниками `lib/models/provider_headers.dart` и реальным Remnawave. Не выдавать предложенный порядок Aeris → FlClashZ → FlClashX или единицы/формат ещё не проверенных значений за пользовательское утверждение. Совместимость проверять fixtures; новая существенная семантика требует согласования. См. [UPSTREAM.md](UPSTREAM.md).
