# Aeris — архитектура

Проектное описание. Имена модулей ниже логические, а не утверждение о существующем коде.

## 1. Разделение процессов

```text
Aeris.exe (WinUI 3, непривилегированный GUI)     aeris (CLI из PATH)
                  |                                  |
                  +--------- Named Pipes ------------+
                                  |
                        AerisCore (служба Windows)
                                  |
                         aeris-core.exe (Rust)
           +----------+----------+----------+----------+
          Config    VPN/TUN     DNS       DPI       API/metrics
                       |         |         |
                   Routing / shared metadata / resources
                       |                   |
                     Wintun             WinDivert
```

Схема логическая: служба контролирует жизненный цикл и привилегированные операции; точное разделение IPC endpoint между службой и ядром проектируется с учётом ACL. Ядро поддерживает foreground/headless/служебный запуск, portable и непривилегированный режим с явным сообщением о недоступных привилегированных функциях. GUI и CLI могут работать одновременно. Единый экземпляр ядра на выбранном IPC endpoint; операции сериализуются. Сбой GUI не останавливает ядро; сбой модуля восстанавливает модуль, если процесс жив; фатальный сбой процесса затрагивает все его модули.

CLI `aeris` доступен в pwsh и скриптах независимо от рабочей директории. Установщик регистрирует PATH, standalone-поставка имеет регистрацию/удаление собственного PATH без повреждения чужих записей. Из-за конфликта `Aeris.exe` и `aeris.exe` в Windows выбрать и протестировать обёртку или отдельный каталог с однозначным поиском; не полагаться на различие регистра или профиль PowerShell. Проверять `Get-Command aeris` при установленном GUI и в portable. Абсолютные и относительные пути конфигов; JSON (`--json`), отключаемый цвет, коды завершения, help, автодополнение pwsh.

Команды (семантика согласована, точные аргументы будут задокументированы после проектирования CLI): `start`, `stop`, `restart`, `status`, `version`, `run -c <path>`, `vpn start|stop|restart`, `zapret start|stop|restart|strategies|select|test`, `dns restart|flush`, `config test|reload`, `proxy list|select|test`, `logs`, `diagnose`, `update`, `help`. `start` не должен неявно включать все модули. Отдельные команды службы/регистрации PATH нуждаются в спецификации. Управление запущенным процессом — через IPC, не запуск второго ядра.

## 2. Внутренние модули

| Модуль | Обязанности |
|---|---|
| Lifecycle | Состояния, старт/остановка, контроль отмены, health, watchdog |
| Config | Парсинг, типизация, валидация, immutable snapshots, reload/rollback |
| Transport | TCP/UDP, асинхронные сокеты, пулы, backpressure, таймауты |
| TLS | rustls с нужной адаптацией, профили отпечатков, REALITY и проверенные криптопримитивы |
| Protocols | Адаптеры исходящих протоколов и XHTTP/XUDP |
| TUN | System, RIPS, Mixed, Auto; драйвер, маршруты, IPv4/IPv6 |
| DNS | Резолверы, политики, Fake-IP, кэш, hijack, защита утечек |
| Routing | Компиляция правил, группы, health checks, выбор исходящего маршрута |
| Sniffer | Метаданные HTTP Host/TLS SNI/QUIC в пределах возможностей без MITM |
| DPI | Rust-реализация Zapret2, Lua runtime, списки, преобразование стратегий |
| Resources | Проверка, атомарное обновление и откат подписанных ресурсов |
| API/IPC | REST/WS совместимость, native IPC, события, capabilities |
| Observability | Метрики, журналы, диагностика, отчёты без секретов |

Cargo workspace; не создавать C-FFI движок Zapret или отдельные процессы winws. Внешние подписанные драйверы Wintun/WinDivert допустимы. Lua — существующий runtime через mlua, выбор сборки/версии после тестов API. TLS-библиотека rustls адаптируется без самописной криптографии. Источники отпечатков: uTLS, FlClashX, проверенные данные реальных браузеров и другие лицензируемые источники; ежедневная проверка, подпись, история, откат; REALITY и ML-KEM проверять на совместимость. Запрещены молчаливые несовместимые подстановки профиля.

## 3. Сетевой путь

Вход TUN/локальный proxy → определение метаданных (DNS/Fake-IP/sniff/process) → первое совпадение пользовательского или провайдерского правила → группа/исходящий маршрут → DIRECT либо транспорт прокси. DPI по умолчанию на подходящих DIRECT-потоках, с исключением сокетов VPN-транспорта и служебного трафика, явная политика для ZAPRET/DIRECT-NO-ZAPRET. Трафик DNS использует свои утверждённые маршруты; избегать циклов DNS↔proxy bootstrap. Standalone DPI может работать без захвата VPN. Нужны тесты исключения повторного перехвата/зацикливания и согласования WFP/WinDivert/TUN.

System: системный стек. RIPS: Rust-порт MIPS. Mixed: TCP System, UDP RIPS. Auto: обоснованный выбор с наблюдаемым состоянием и без ослабления безопасности. Не эмулировать gVisor. Сохранять IPv4/IPv6 и per-module исключения (IP/приложения/интерфейсы там, где поддержано). Выбор семейства IP и политики IPv4/IPv6 отдельно для сетевых модулей; Happy Eyeballs, NAT64/DNS64 при настроенной поддержке; BBR3/CUBIC — по реальным возможностям реализации и тестам, не подмена параметра названием.

Tokio, ограниченные очереди/буферы и backpressure, отмена операций при остановке, адаптивные таймауты; CPU dispatch SSE/AVX2/AVX512, AES-NI/VAES/SHA/BMI по наличию и пользе. Не задавать произвольную affinity. Сравнительные бенчмарки определяют размеры кэшей, пулы и настройки. Снимки правил атомарны; активные соединения сохраняют выбранный маршрут по умолчанию до завершения, если политика безопасности не требует немедленного прекращения.

## 4. DNS

Резолверы UDP/TCP, DoH h1/h2/h3, DoT, DoQ; опциональный DNSSEC, TLS verification, optional pin, ECS opt-in, stamps при поддержке. Системный DNS — только явная настройка. Группы DNS select/parallel/sequential/fallback/load-balance/smart, отдельный маршрут для DNS, bootstrap и полное respect-rules, nameserver-policy, hosts, суффикс маршрута `#<группа>`. Без незаявленного публичного fallback. Возможна отдельная политика DNS для Zapret2. DNS Always On и DNS Proxy Access — независимая работа DNS и внутренних прокси-доступов при отключённом пользовательском VPN, с соблюдением ограничений и Kill Switch.

Fake-IP/Redir-Host/Hybrid: раздельный DNS-кэш и таблица Fake-IP IPv4/IPv6, стабильные соответствия, исключения, отсутствие fake-адресов во внешних запросах, интеграция маршрутизации/sniffer/DPI. TTL/negative cache/prefetch/serve-stale/coalescing, опциональное дисковое хранение раздельно; алгоритм вытеснения выбирается бенчмарками: сравнивать hit rate, p50/p95/p99 latency, throughput, расход RAM/CPU, поведение при смене сети и различных распределениях запросов. Это критерии инженерного выбора, не заранее заданные численные пороги. Пулы, TLS resumption, health, delayed racing, warmup/preconnect при пользе, реакция на смену сети.

Hijack UDP/TCP 53 IPv4/IPv6; standard (default), strict, custom, off; fail-closed для настроенной политики. Опционально блокировать известные внешние DoH/DoT endpoints без MITM; нельзя обещать обнаружение всех шифрованных DNS. Защита rebinding с явными исключениями. Раздельная очистка DNS/Fake-IP, атомарное обновление, диагностика утечек и задержек. Sniffer HTTP Host/TLS SNI/QUIC без расшифровки прикладных данных; ECH ограничивает видимость.

## 5. Маршрутизация и мониторинг

Первое совпадение; домен/IP/ASN/процесс/порты/протокол/интерфейс/логические выражения и утверждённые sub-rules. Общие неизменяемые снимки данных, tries/индексы и кэш без нарушения порядка. Rule/global/direct/zapret-only/custom в поддерживаемых сценариях; группы select/url-test/fallback/load-balance/smart/adaptive, weights/sticky/least latency/least connections. Smart выбирает подходящий узел, adaptive распределяет с учётом доступной пассивной статистики (RTT, jitter, TTFB, loss, скорость), без выдуманной нагрузки удалённого сервера. Профили gaming/streaming как политика, не обещание улучшения. Health при старте/по интервалу/lazy; общий dedup проверки узла+URL, ICMP отдельно от proxy request delay, несколько тестовых URL при поддержке. Непрерывный speedtest не выполнять. GeoIP/GeoSite/MRS/MMDB/YAML/text providers, кеш/обновление/история/rollback/источники. dialer-proxy для цепочек.

Kill Switch: off, proxy-only (default), strict, persistent согласно контракту; WFP и тесты на аварии. Не ослаблять правило автоматически при недоступном прокси. Точное значение режимов закрепить в YAML/API до кода. Соединения: live counters, правило/маршрут/DPI отдельно, закрытие отдельного/всех/по приложению при поддержке, настройки таймаутов, сохранение маршрута при обновлении. Диагностика симуляции правил, конфликтов и попаданий.

## 6. Zapret2

Rust-порт поддерживаемых механизмов оригинала; не Zapret1. Режимы: rules-only/STRICT SPLIT и FULL BYPASS в пределах поддерживаемых стратегий, standalone/custom. Flowseal BAT — анализ и конверсия в семантику Zapret2 (Zetklif как референс), не выполнение команд; не обещать перенос неподдерживаемых Zapret1 опций. Lua API проверяется против оригинала; Ultimate и свои стратегии могут иметь собственные ограничения, UI сообщает о них. Ограничение времени/памяти/доступа к файловой системе, без произвольного системного исполнения, валидация путей и аргументов. Сохранять оригинал стратегии, показывать ошибки конверсии; изоляция недоверенного кода требует отдельной проверки модели угроз.

Списки hostlist/IPSet/auto/exclude, пользовательские и провайдерские источники, provenance, дедуп, исключения приоритетнее включений, конфликтующие записи видимы. Обновление атомарно и с совместимостью движка. Автоподбор quick/standard/extended/custom, заданные цели, историю сохранять; применение результата вручную по умолчанию, не менять стратегию молча. Четыре основных HTTPS-проверки YouTube, GoogleVideo, Discord Gateway, Discord Voice API; отдельно можно проверять QUIC, но не считать HTTPS Voice доказательством доступности UDP-голоса. Все через нужный DIRECT-путь и DNS ядра. Ручное переключение сетевого профиля по умолчанию, наблюдение/автоопционально. Проверять драйвер, конфликты, античиты без вмешательства в них, CPU/ОЗУ, DNS, логи.

## 7. API и хранение

Совместимый Clash REST/WebSocket плюс собственный версионированный API; native Named Pipes с MessagePack, external JSON. Событийные изменения вместо постоянного polling, трафик/соединения ~1 с, CPU/DNS/DPI агрегаты ~2 с, статус немедленно; shared memory лишь при доказанной пользе. Нативный API и IPC начинают с v1, версионируются независимо и объявляют capabilities. Локальный API default, remote off, ACL/token, read/operator/admin/custom capabilities, привилегированные действия авторизованы отдельно. Не принимать произвольные команды. GUI не выполняет сетевое управление напрямую.

Настройки установленного клиента LocalAppData, portable рядом с программой, служебные общие данные в ProgramData при необходимости; ACL, DPAPI для токенов. YAML подписок read-only; настройки JSON/YAML, SQLite для истории/статистики где необходимо. Нет общей пользовательской резервной копии настроек. Внутренние атомарные snapshots для rollback допустимы.

Логи tracing, модули off/error/warn/info/debug/trace, память/файл/hybrid; default warn, 8 МБ memory, disk off; DNS safety 4 МБ memory только ошибки/безопасность по умолчанию; журнал запросов не включать по умолчанию, отдельная настройка полей/анонимизации/исключений и ограничений, без раскрытия чувствительных данных, DPI basic 4 МБ, Lua warn/trace off. История соединений off, live/aggregates on; при включении SQLite 7 дней/100 МБ (настраиваемо); без payload. История автоподбора on. Неблокирующие буферы, счётчик отброшенных сообщений, redaction секретов, scrubbed export без автоматической отправки. Метрики отдельно от журналов.

## 8. Надёжность и обновления

Служба с watchdog и backoff, ограничение циклов перезапуска, safe mode, причину записывать в журнал. Атомарные настройки/ресурсы, migration rollback. Восстанавливать собственные сетевые объекты после сбоя без разрушения чужих. Kill Switch не обходить даже при рестарте. Совместимость IPC до обновления; подписанные manifest, hashes, доверенные ключи вне управляемого провайдером URL, откат. Отдельные обновления ядра, клиента, службы, Wintun, WinDivert, Lua-ресурсов, TLS, стратегий/списков и геоданных. Драйверы с подтверждением; без самопроизвольного удаления общих драйверов. Загружать только изменившиеся компоненты; явный возврат Nightly → Release при совместимости и безопасной миграции.

При недостатке RAM освобождать безопасно вытесняемые кэши с backpressure, не удаляя активные соответствия Fake-IP и данные, необходимые для текущей политики. При повреждении ресурса: обнаружить ошибку проверки целостности, не активировать повреждённый ресурс, восстановить последнюю проверенную совместимую копию или скачать и проверить новую; если безопасной копии нет, явно сообщить ошибку и не ослаблять политику. После смены сети/сбоя DNS восстанавливать configured resolver/policy и пулы с ограниченными повторами; никаких скрытых системных или публичных fallback. Проверять сохранение активных соединений там, где безопасно.
