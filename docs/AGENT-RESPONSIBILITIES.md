# Координация оркестратора Codex

Главный оркестратор управляет исполнителями и интеграцией. Ниже предлагаемая рабочая декомпозиция, не новый функциональный scope и не утверждение о доступности конкретных моделей. Названия агентов и модели в Codex выбираются владельцем; не менять их настройки из репозитория.

| Роль | Ответственность |
|---|---|
| Оркестратор | DAG задач, назначение владельцев файлов/контрактов, интеграция трёх репозиториев, приоритеты, merge gates, отчёт |
| Архитектор | Единая schema/API/IPC, границы модулей, lifecycle, версии, угрозы, review совместимости, решение технических конфликтов |
| Сетевое ядро | Rust config/transport/TLS/protocol/DNS/routing/TUN; протоколы и эталоны, тесты с серверами |
| DPI / ресурсы | Нативный Rust Zapret2/Lua, Flowseal на Zapret2, импорт и обновление, списки, подписи и provenance, независимость VPN |
| Интерфейс | Нативный WinUI 3, выбор внутренней UI-библиотеки по D-26, оба фиксированных режима, страницы, персонализация, локализация, accessibility; только IPC для управления ядром |
| Системная интеграция | Служба, IPC, Windows драйверы, CLI PATH, install/portable, обновления и CI; контракт с архитектором |
| Безопасность | Независимый review ACL, crypto, DNS/IP leaks, Lua sandbox, Kill Switch, зависимостей, лицензий и подписей |
| Тестирование | Независимые тесты, fixtures, interop, real Windows, нагрузка/72h, regression, evidence; не отмечать незапущенные проверки как PASS |

При передаче задач указать этап и действующие границы. Для архитектуры и системной интеграции сохранить независимость VPN/DNS/DPI и версионируемый IPC. Для сетевого ядра использовать общую реализацию WireGuard/AmneziaWG на этапе 6, для DPI соблюдать приоритет эталонов на этапе 10. Для GUI оставить возможность будущих точек WinUI 3. Для безопасности и QA проверять изоляцию, права и совместимость по фактическим реализациям. Текущая разработка сохраняет порядок ROADMAP.

DevOps ведёт CI/CD и бюджет hosted runners. Architect согласует границы переиспользования и межрепозиторный контракт. Security проверяет доверие к кэшам, артефактам и подписи. QA выполняет матрицу режимов и измерения. Reviewer независимо проверяет изменения перед интеграцией.

По D-26 Architect проверяет границы и варианты, Core — качество Rust-реализации, System — Windows, Security — лицензию и безопасность, QA — воспроизводимые результаты, DevOps — сборку и поставку, Docs — согласованность, Reviewer — самостоятельную итоговую оценку. Оркестратор опирается на доказательства и организует дополнительную проверку при расхождении выводов.

## Передача задачи

Каждой задаче назначить репозиторий, каталог и область записи, ветку и base SHA, этап, ID требований, применимые документы, действующие и отменённые решения, defaults, владельца файлов, контракт, результат, зависимости и тесты. Повторно сверить решение и diff после изменения требований. Разрешать параллельную работу только на непересекающихся файлах или согласованных контрактах. Изменение общего YAML/API/IPC согласовать с архитектором и оркестратором до реализации; сообщить всем потребителям. Не создавать отдельные реализации одинаковой функции.

Исполнитель возвращает конкретный diff/commit/PR, команды и результаты проверок, evidence, ограничения и риски. Оркестратор сверяет требования, выполняет интеграционные тесты, не сливает при fail. Независимые агенты безопасности/тестов могут блокировать merge до устранения проблемы. Сначала read-only проверка текущих репозиториев и незавершённых PR. Не сбрасывать ветки и не переписывать чужую историю.

При существенном TBD предложить варианты и один конкретный вопрос владельцу. Уже утверждённое не пересогласовывать; спорные выводы из ранних обсуждений сверять с DECISIONS. Не включать новые функции без согласования. Нельзя считать mock, parser option или UI toggle подтверждением работающего модуля.
