# Transport implementation status / Статус сетевого транспорта

Initial isolated transport crate, stacked on the configuration work; not a running VPN.

- Tokio 1.54.1 (MIT metadata at the verified upstream tag), with explicit minimal features and Cargo.lock to be generated by CI and checked in.
- TCP connect, partial read/write, address metadata and write half-close; UDP bind/send/receive with caller-provided buffers. Numeric SocketAddr only: no hidden DNS, routing decision, retries, proxy fallback or automatic DIRECT.
- Shared lifetime capacity via semaphore, including connect/bind attempts; RAII release on handle drop. Separate capacity, connect and I/O deadlines; shutdown wakes pending operations and prevents new I/O. Owners must still drop idle handles. This is not WFP/Kill Switch enforcement.
- Typed redacted errors, no background network work, no unbounded internal message queues. The first implementation does not limit how many callers may queue tasks outside this module; a bounded dispatcher remains to be implemented. UDP uses a conservative portable send size and full-size receive buffer; no IPv6 jumbograms.
- Initial internal limits (not new YAML keys): 256 sockets; capacity wait 5 s, connection 10 s, I/O 30 s; TCP_NODELAY enabled. These are provisional until benchmarks; no performance claim.
- Windows loopback tests: TCP echo/half-close, UDP echo, buffer limits, capacity release, read deadline, shutdown cancellation. Tests use only local sockets. No traffic interception, TLS, protocol adapter, IPv6-specific tests, route binding, real-world congestion tuning or driver tests yet.
- Do not wire direct transport to GUI/CLI or turn it into a network service until routing, DNS policy and lifecycle contracts are implemented.
- Before merging: lockfile, formatting, Clippy, automated tests, Windows build, dependency license/advisory review.
